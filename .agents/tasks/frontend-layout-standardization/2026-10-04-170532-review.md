# Frontend layout standardization across the Vue views

This change centralizes shared page-layout rules so every main view composes an identical shell: a 220px sidebar, a 1200px centred content column, a 240px hero banner with a bottom-left title overlay, and a solid dark fill on views that previously carried full-page background art. New shared primitives live in `main.css` (`.page-container`, `.page-sections`, `.app-hero*`, `.page-plain`) and on `AppLayout.vue`'s `<main>`; each in-scope view drops its bespoke hero/width CSS and consumes the shared classes. The diff also fixes the duplicate "Your Campaigns" heading, swaps the Campaigns New Campaign button to the dashboard art asset, restyles the About page spacing, and restructures Join Session so the form renders independently of the load-error panel.

Watch for: section spacing is **not** uniform — AI Settings and Adventure Forge separate their major sections with `space-y-6` (24px) and Rules Lookup's content column does the same, while Campaigns/Characters/Library use the shared 32px `.page-sections` (confirmed). This misses requirement #1's explicit "32px vertical gap between major sections on every view" and leaves exactly the cross-view inconsistency the task set out to remove.

**Verdict**: NEEDS_CHANGES

## High-level view

The shell changes are solid and genuinely centralized. `AppLayout.vue` wraps the slot in `.page-container` (max-width 1200px, `margin:0 auto`, `padding:0 32px 48px`), `AppSidebar.vue` pins the expanded width to 220px with `shrink-0`, and the per-view `mx-auto max-w-*` wrappers were removed everywhere in scope so the shell width wins. The sidebar being a single shared component means 220px now applies to the Dashboard too.

Background removal is clean and correct. All five named views (Rules Lookup, AI Settings, Adventure Forge, Join Session, About) drop their full-page `v-bg-asset` and gain `.page-plain` (opaque `#0a0a1a`) so the body `app-background.png` can't bleed through; the old `background-attachment:fixed` and negative-margin full-bleed hacks are gone. The one remaining `*-background.png` reference in Adventure Forge is an inner panel's art, not a page background. Dashboard/Campaigns/Library/Characters backgrounds are untouched.

The hero standardization works but exposes the spacing gap. Every non-dashboard view now uses `.app-hero` (240px) with the title/subtitle in `.app-hero__overlay` bottom-left, and the Dashboard keeps its own taller hero. But the shared 32px section rhythm was only applied to three views via `.page-sections`; AI Settings and Adventure Forge kept `space-y-6` top-level wrappers, so their hero-to-content gap is 24px while the others are 32px.

The targeted bug fixes land. "Your Campaigns" now appears exactly once (in `CampaignList.vue`), the Campaigns button uses `new-campaign-button-art.png` at `size:100% 100%` with CSS dimensions matching HomeView, the About hero/spacing values match the spec (40px gap, 32px card padding, 28px/32px panel padding), and Join Session renders the form in an unconditional `v-else` with the not-found panel as a sibling below it rather than an `v-else-if` that hid the form.

### Shell centralization: sidebar, container, hero

`AppLayout.vue` now wraps `<slot/>` in `<div class="page-container">` inside a `<main class="flex-1 overflow-y-auto pt-6">`. Top padding comes from `pt-6`; `.page-container` supplies `padding:0 32px 48px 32px`, max-width 1200px, and auto margins. Every in-scope view had its own `mx-auto max-w-5xl/max-w-3xl/max-w-2xl` removed (and HomeView's `mx-auto max-w-6xl`), so the shell is the single width authority. JoinSession deliberately keeps an inner `max-w-lg` for its narrow focused form, nested inside the centred shell — a reasonable exception, not a regression.

The sidebar fix replaces Tailwind `w-60` (240px) with a scoped `.sidebar-expanded { width:220px }` and adds `shrink-0` so flex can't squeeze it. Because `AppSidebar.vue` is a single shared component, this is 220px on the Dashboard and every other route (confirmed — the "Dashboard sidebar narrower" report had no code basis; pinning the width addresses the symptom regardless).

The hero primitives (`.app-hero` min-height 240px, `.app-hero__overlay` absolute bottom-left `padding:24px`, `.app-hero__title` 24px/700/#fff, `.app-hero__subtitle` 14px/#9ca3af) are applied to Campaigns, Characters, Library, Rules Lookup, AI Settings, Adventure Forge, Join Session, and About. Each view's old bespoke `.hero`/`.library-hero`/`.forge-hero`/`.settings-hero` (all 120–180px) and their scoped CSS were deleted, so there's no per-view hero divergence left and the banner art stays on the hero's own element.

### Section spacing inconsistency (confirmed)

Requirement #1 asks for a 32px vertical gap between major sections on every view. The implementation only delivers this on the three views that adopted `.page-sections` (Campaigns, Characters, Library). Rules Lookup uses `.page-sections` at the top level (hero → content column gap is 32px) but its content column is `space-y-6` (24px). AI Settings (`<div class="space-y-6">` at line 289) and Adventure Forge (`<div class="space-y-6">` at line 93) use 24px at the top level, so even their hero-to-first-section gap is 24px.

The result is directly visible when navigating: the hero-to-content gap is 32px on Campaigns/Characters/Library/Rules Lookup and 24px on AI Settings/Adventure Forge. That is the cross-view inconsistency requirement #1 was meant to eliminate, and `verification.md` overclaims it ("shared 32px section rhythm are all driven from AppLayout.vue + main.css") when the 32px rhythm was never applied to those two views. About is fine here — it uses `.about-sections` at 40px, which satisfies both the ≥32px baseline and the About-specific 40px requirement.

### Background removal (confirmed correct)

All five named views drop the full-page image directive and add `.page-plain`. The removed CSS is thorough: `.ai-settings-page`/`.forge-page` `background-size/position/attachment:fixed`, the `.forge-page { margin:-1rem }` and `.join-page { -m-6 }` full-bleed hacks, and the `bg-cover bg-fixed bg-center` root classes on Rules Lookup/About/Adventure/Join. A grep of the five views for `background.png`/`bg-fixed`/`background-attachment` returns only one hit — `adventure-forge-panel-background.png` on an inner forge panel — which is intended panel art, not a page background. Inner panels keep their gold borders and panel art, so they stay distinct against the dark fill. Dashboard/Campaigns/Library/Characters never had a full-page image and the `main.css` body `app-background.png` is untouched.

### Campaigns: heading and button

The duplicate heading is resolved by removing `<h2>Your Campaigns</h2>` from the CampaignsView page-header row while keeping the New Campaign button in that row (now `justify-end`). A grep confirms the only remaining occurrence is in `CampaignList.vue:75`, above the card list — exactly where the task wants it.

The button swap matches the spec: `v-bg-asset="{ url:'/assets/dashboard/new-campaign-button-art.png', fallback:'transparent', size:'100% 100%' }"` with `.new-campaign-button` CSS (min-width 180px, min-height 44px, gold border, md radius) identical to HomeView's, and "+ New Campaign" as overlaid text. The old purple `.btn-primary` with its SVG icon is gone. The purple `background-color` remains only as an art-independent fallback behind the `100% 100%` art — consistent with the HomeView pattern. The only nit is that the button CSS is copied rather than shared, inviting future drift.

### Join Session form/error ordering (confirmed fixed)

The template was restructured from a `v-if loading → v-else-if (error && !currentSession) → v-else-if joinResult → v-else-if currentSession` chain (which hid the form whenever the session failed to load) to `v-if loading → v-else-if joinResult → v-else`. The `v-else` block always renders `PlayerJoinForm` + the QR card, with `:session-name="store.currentSession?.name"` made optional so it renders even when no session loaded. The not-found panel is now a sibling inside that block, guarded by `v-if="store.error && !store.currentSession"`, placed after the QR card — form first, error below, exactly as required.

No double-error risk: `PlayerJoinForm.vue` contains no reference to `store.error` (grep returns nothing), so the standalone not-found panel is the only place the load error surfaces. The verification note's rationale about PlayerJoinForm "surfacing the same error" is moot but harmless.

### About spacing (confirmed)

`.about-sections` sets a 40px flex gap (≥40px requirement met), `.license-card { padding:32px }`, and `.about-panel { padding:28px 32px }`, with the conflicting Tailwind `p-5` removed from those template elements so the scoped padding is authoritative. The hero uses `about-hero-banner.png` on `.app-hero` with the title overlaid, matching the other views.
